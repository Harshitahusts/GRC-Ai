The client gives read-only access to your firm's AWS account, so this computer needs that account's credentials:

  1. In your firm's AWS account, create an IAM user for this app with only the permission sts:AssumeRole.
  2. Create an access key for it and run aws configure on this computer (or set AWS_ACCESS_KEY_ID and AWS_SECRET_ACCESS_KEY in .env). To use a named profile, set GRC_AWS_PROFILE.
  3. Restart the app and reload this page.

Authorise read-only access

The client creates a read-only role in their AWS account that only your firm's account can use, locked to this engagement. No keys are shared, and they can remove it at any time.

  1. Download the CloudFormation template and send it to the client.
  2. The client opens CloudFormation → Create stack → With new resources → Upload a template file, chooses the file, and creates the stack.
  3. When it finishes, they copy RoleArn from the stack's Outputs tab and send it to you.
  4. Paste it below.

Creating the role by hand instead
  1. IAM → Roles → Create role → AWS account → Another AWS account, account ID {{ firm_account }}.
  2. Tick Require external ID and enter {{ external_id }}.
  3. Attach the policy SecurityAudit, name the role, create it, and send its ARN.

To remove access, the client deletes the stack (or the role).
